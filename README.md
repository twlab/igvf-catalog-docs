# IGVF Catalog Documentation

Documentation for the [IGVF Catalog](https://catalog.igvf.org) data model, UI, REST API, and data provenance.

**Published sites** (GitHub Pages project site for this repository):

- Development API: https://igvf-dacc.github.io/igvf-catalog-docs/dev/
- Production API: https://igvf-dacc.github.io/igvf-catalog-docs/main/
- Index: https://igvf-dacc.github.io/igvf-catalog-docs/

Example API intro pages:

- https://igvf-dacc.github.io/igvf-catalog-docs/dev/api-reference/introduction/
- https://igvf-dacc.github.io/igvf-catalog-docs/main/api-reference/introduction/

Note: URLs like `https://igvf-dacc.github.io/dev/` require an organization-level GitHub Pages site (a separate `IGVF-DACC.github.io` repository). This repo publishes under `/igvf-catalog-docs/` automatically.

## Contents

- **Nodes & regions** — genes, variants, proteins, transcripts, diseases, ontologies, and UI guides
- **API Reference** — auto-generated from the Catalog OpenAPI spec (dev or production)
- **Data Sources** — IGVF/ENCODE portal file metadata and field lineage (portal → adapter → API)

## API environments

Two documentation trees are built and deployed in parallel:

| Tree | Base path | API base URL | OpenAPI config |
|------|-----------|--------------|----------------|
| Development | `/igvf-catalog-docs/dev/` | `https://catalog-api-dev.demo.igvf.org/api` | [`openapi/config-dev.json`](openapi/config-dev.json) |
| Production | `/igvf-catalog-docs/main/` | `https://api.catalogkg.igvf.org/api` | [`openapi/config-main.json`](openapi/config-main.json) |

## Local development

Install the [Mintlify CLI](https://www.npmjs.com/package/mintlify):

```bash
npm install -g mintlify
```

Refresh generated content for a variant and preview:

```bash
./scripts/build_docs.sh dev
mintlify dev
```

Use `./scripts/build_docs.sh main` for the production API spec.

Configuration lives in [`docs.json`](docs.json) (Mintlify v4, generated by [`scripts/prepare_docs_variant.py`](scripts/prepare_docs_variant.py)). Site-wide styling overrides are in [`custom.css`](custom.css).

GitHub Pages serves two static trees at `/igvf-catalog-docs/dev/` and `/igvf-catalog-docs/main/`. The deploy workflow runs [`scripts/build_static_site.sh`](scripts/build_static_site.sh) and [`scripts/patch_github_pages_basepath.py`](scripts/patch_github_pages_basepath.py) after each Mintlify export so asset URLs and navigation resolve correctly.

## Build scripts

| Script | Purpose |
|--------|---------|
| [`scripts/prepare_docs_variant.py`](scripts/prepare_docs_variant.py) | Configure docs.json and API intro for dev or main |
| [`scripts/build_static_site.sh`](scripts/build_static_site.sh) | Export and patch one GitHub Pages tree |
| [`scripts/fetch_openapi.py`](scripts/fetch_openapi.py) | Download OpenAPI from Swagger UI |
| [`scripts/build_source_index.py`](scripts/build_source_index.py) | Resolve IGVF/ENCODE file metadata + format specs |
| [`scripts/build_field_lineage.py`](scripts/build_field_lineage.py) | Adapter → field mapping docs |
| [`scripts/sample_responses.py`](scripts/sample_responses.py) | Store example API responses |
| [`scripts/catalog_per_example_audit.py`](scripts/catalog_per_example_audit.py) | Validate doc examples against live API |

## Deployment

Pushes to `main` trigger [`.github/workflows/deploy-pages.yml`](.github/workflows/deploy-pages.yml), which builds both `/dev/` and `/main/` trees and deploys them to GitHub Pages.

Repository Settings → Pages → Source: **GitHub Actions** (one-time setup).
